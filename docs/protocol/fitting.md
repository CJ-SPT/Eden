## Personal saved fitting plans (November 6, 2026)

The user reported **Invalid Packet Destination: Unsupported local call charFittingMgr.SaveFitting** while saving a Brutix Navy Issue fitting. Eden previously returned an empty dictionary for personal fitting reads and had no save implementation. This milestone adds personal plan storage without fitting equipment, buying items or changing the active ship.

Inert inspection of pinned build **3662168** `eve/client/script/environment/fittingSvc.pyj` confirms `SaveFitting(ownerID, fitting)` returns a positive fitting ID; `UpdateFitting(ownerID, fitting, fittingID=...)` overwrites an existing ID; `GetFittings(ownerID)` returns a dictionary keyed by fitting ID. `DeleteFitting(ownerID, fittingID)` and `UpdateNameAndDescription(fittingID, ownerID, name, description)` return None. Each fitting is `utillib.KeyVal` with `name`, `description`, `shipTypeID`, `fitData` and `ownerID`; saved replies additionally include `fittingID` and FILETIME `savedDate`. `fitData` remains an ordered Python list of **(typeID, flag, quantity)** tuples. Names/descriptions retain Unicode and quantities retain integer wire forms.

Native `PersistFitting` updates the local cache itself only for an overwrite. A newly saved fit needs **OnFittingAdded(ownerID, fittingID)** after the successful reply: the native handler invalidates the primed fitting dictionary when that ID is absent, allowing the next draw to fetch the new entry. Eden queues this notification only after a committed create. Rename, overwrite and delete retain the client's existing reply-driven cache updates.

The handler derives the owner from the selected pilot and checks the explicit owner argument and any payload owner field against it. Fitting IDs are owner-scoped for updates, renames and deletion. Saving is allowed both docked and in space; a template does not require owning its listed equipment or meeting fitting/skill/capacity requirements. The catalog must contain a ship or structure hull and every listed item type. Gameplay checks the pinned **50-character name**, **500-character description**, **500 personal fitting** limit, nonempty data, positive quantities, reserved `@@` marker and allowed fitting/cargo/drone/fighter flags. The flag set follows `inventorycommon.const.fittingFlags` and `IsShipFittingFlag`, including three rig, four subsystem and eight service positions, plus hidden modifiers. Eden additionally bounds a template to **1024 entries**. Corporation/alliance storage and bulk import are deferred; their support is not implied by saving a personal plan.

World schema **84** adds `WorldSavedFitting`, with an autoincrement ID, pilot foreign key, owner index, hull, name, description, typed-item JSON and save timestamp. Creates enforce the per-pilot quota inside the same transaction as the insert; overwrites preserve IDs and remain available at the quota. Related fields commit together. Reopening retains plans and deletions. Schema version **83** is reserved for concurrent NPC mining work; that work will create its tables idempotently even for saves already upgraded to version 84 by fittings. No runtime database or client files were edited.

## Persistent weapon grouping

Build 3662168's dogma location calls now support `LinkWeapons(ship, master, source)`, `MergeModuleGroups`, `PeelAndLink`, `UnlinkModule(ship, master)`, `DestroyWeaponBank`, `LinkAllWeapons` and `UnlinkAllModules`. Link/merge/peel/group-all return the complete master-to-slave-list map. Unlink returns the detached slave ID. Destroy and ungroup-all return None. The client updates its bank cache from these replies. The third member of the four-member ship-state tuple carries the same map for login and boarding. Fitting changes notify `OnWeaponBanksChanged(ship, banks)`.

Gameplay owns typed grouping rules. Supported online high-slot weapons group by exact module type. Merge combines banks, peel moves one slave, unlink detaches one slave and destroy dissolves a bank. Group-all builds one bank per module type in slot order. Ownership, active ship, supported/online modules, active effects and paid cycle/reload deadlines are checked before changes. World schema **70** adds `WorldWeaponLink`, with cascading ship/module references. Existing worlds start with empty banks. Unfitting, offlining and automatic resource shutdown prune invalid membership within the fitting transaction. Destruction cascades through existing inventory cleanup.

A turret bank has one repeating controller and one damage settlement per volley. Each member pays ammunition, independent crystal wear, capacitor and cooldown, with independent accuracy draws. All members prepare in one transaction before combined damage is applied, including fatal volleys. An invalid member rolls back the entire payment and damage. The owner receives each magazine and module effect, all turret space effects and one banked combat message per volley. The bank waits for its slowest cycle and stops as a unit. Missile banks keep one native projectile per launcher, with one atomic launch transaction and one repeating bank controller. Existing projectile impact handling settles each warhead. Reload/unload expands scalar or list bank requests to distinct members. A partial ammunition stack is shared across the bank's remaining magazines. A grouped load that leaves a member without the requested ammunition rolls back.

Iron Charge S **215** and Antimatter Charge S **222** each occupy **0.0025 m³**, making 200 rounds per full magazine. The default firing effect is **34 / projectileFired / effects.ProjectileFired**, even for this railgun. These shapes reuse the existing Blue and Destiny codecs and their previously recorded Carbon revisions.

The starter policy adds the 75mm gun at **1,000 ISK**, plus Iron and Antimatter at **1 ISK per round**, with finite stocks of 100 guns and 100,000 of each charge at visited market stations. Existing orders, stock and history stay intact. Other small Tech I hybrid types can use the family implementation when available as owned equipment; the starter market initially offers only the 75mm gun. Required skills, high-slot/turret limits and combined CPU/grid remain enforced.

Pinned `DogmaLocation.LoadChargesToModule` and `LoadAmmoToModules` call `dogmaIM.LoadAmmo(shipID, moduleIDList, chargeItemIDList, ammoLocationID)`. `UnloadAmmoFromModules` passes a module list; `UnloadAmmoToContainer` passes a single module, a `(locationID, ownerID, flagID)` destination and optional quantity. The HUD's native unload menu uses current-ship cargo. One ammunition handler owns both methods; source IDs must be distinct owned stacks of one compatible charge type in ordinary cargo or the current docked station hangar. Unload supports partial quantities for a single module. Invalid batches and capacity failures roll back the entire transfer.

Loaded rounds remain actual owned stacks whose durable `LocationId` is the fitted module's ID. They are absent from ordinary cargo until unloaded. The wire identity is the native **(shipID, flagID, chargeTypeID)** sublocation. Godma primes carry a null `invItem`, that tuple identity, charge attributes including **805 / quantity**, and no active effects. Mixed-key `shipInfo` uses the existing `BlueDictionary` type. `shipState.instanceFlagQuantityCache` contains a four-column native DBRow `(locationID, flagID, typeID, quantity)` per slot, as consumed by `BaseDogmaLocation.LoadSublocations` and `GetQuantityFromCache`. Quantity changes use the tuple as the item key; zero quantity removes the exhausted sublocation. The existing reduction opcode now carries the inventory descriptor's reduce state; no new opcode is introduced.

Loading, topping up or swapping consumes only real selected stacks, returns the old charge type to the source, fills available magazine capacity and commits a reload deadline. `OnGodmaPrimeItem`, `OnModuleAttributeChanges` and `OnChargeBeingLoadedToModule(moduleIDs, chargeTypeID, milliseconds)` drive the native charge/count/reload presentation. Attribute **2729 / nextActivationTime** permits the existing `StateManager.GetReloadTimes` calculation after reconnect. World version **25** adds a named `ModuleCooldownKind` to the retained `WorldWeaponCooldown` table; old deadlines become ordinary cycles without being reset. Reload and firing serialize through that same module deadline. Migration grants no equipment, ammunition, skills or ISK.

Each hybrid shot checks owned fitted online state, skills, same-system target/range, compatible loaded rounds and the saved deadline before spending capacitor or ammunition. It spends charge-rate rounds even on a miss. The magazine, capacitor, next cycle, NPC health, aggression, fatal wreck and bounty share one transaction. The existing hit-quality/resistance calculations and gunnery modifiers apply. Small Hybrid Turret adds damage; Ibis's catalog rookie hybrid bonus adds optimal range. Charge effect **596** multiplies range by attribute **120** (Iron **1.6**, Antimatter **0.5**); effect **804** applies capacitor percent **317** (Iron **-30%**, Antimatter **0%**). Ammo supplies the damage mixture: Iron **3 kinetic + 2 thermal**, Antimatter **7 kinetic + 5 thermal**. The civilian gun retains its built-in charge and effect 10.
