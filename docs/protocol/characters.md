## Direct skill purchasing, November 11, 2026

The reported client dialog was `Invalid Packet Destination: Unsupported local call @skills.PurchaseSkills`.
The selected-pilot skill handler now accepts one Python list of skill type IDs and returns a Python list of the purchased IDs.
Successful purchases immediately inject each skill at level zero and zero SP, emit `OnServerSkillsChanged` and `OnAccountChange`,
and retain the ordinary training prerequisites. Purchasing works while docked or in space and creates no inventory skillbook.

The server requires a published skill with a positive finite training rank and base price, eligible under pinned catalog type
list **93**. Category, group and type inclusions/exclusions use the existing native type-list rules. Prices use catalog base
price plus **30%**, rounded to integer cents per skill; testing-market one-ISK pricing does not replace this character-sheet price.
Duplicate, invalid, unavailable or already-injected skills reject the batch. Empty lists return an empty list without changes.
The wallet debits, per-skill `Skill Purchase` journal entries (**141**, with skill type references), skill rows and injection task
progress commit in one transaction. Insufficient funds, competing requests and failed writes cannot charge for unlearned skills.
No schema migration is needed: journal entries use the existing service-payment ledger.

## Character biomass (November 6, 2026)

The maintainer's screenshot reports **Invalid Packet Destination: Unsupported local call charUnboundMgr.PrepareCharacterForDelete** at character selection. The handler was missing all three biomass calls, and selection cards always returned `deletePrepareDateTime=None`.

Inert inspection of pinned build **3662168** `eve/client/script/ui/login/charSelection/characterSelection.pyj` confirms `SubmitToBiomassQueue` calls `PrepareCharacterForDelete(charID)` and uses its numeric FILETIME reply as the deletion-ready deadline. `UndoTermination` calls `CancelCharacterDeletePrepare(charID)`. `Terminate` compares that deadline to wall-clock time; after the native confirmation, `DeleteCharacter(charID)` expects a falsy success result and reloads selection data. `loginCharacterselection/charselData.pyj` reads `deletePrepareDateTime` directly. Eden returns an integer deadline for preparation and Python None for cancel/delete, with no extra notifications.

This milestone initially used a ten-hour cooling-off period; the ten-minute follow-up below supersedes that policy. Repeating preparation retains the existing deadline. Cancellation is idempotent and allows normal selection again; a new preparation starts a fresh deadline. Pending characters retain their slot and cannot enter the game until canceled. Final deletion requires a prepared, owned character at or beyond the saved deadline, then removes it from account lookup and selection and frees its slot. Selection refreshes its roster before accepting an ID, so stale cards cannot restore access. Malformed calls, extra keywords, foreign or unknown IDs and calls made after character selection reject without writes. The host already allows only one connected session per account.

World schema **93** adds `WorldCharacterDeletion` with ready and deleted timestamps. Final deletion is a permanent tombstone: identity, name reservation, assets and public/historical references remain saved; IDs are never reused. Owned ship positions and the training queue are removed in the same transaction so a deleted pilot cannot remain an in-space target or keep training. Assets are inaccessible through that character and are not transferred to another pilot. Player-corporation membership, open personal market orders, undelivered industry jobs, and unresolved issuer/acceptor/bidder contracts must be settled first. These checks run for initial preparation and again at final deletion; cancellation remains available. This avoids orphaning corporate leadership, escrow or counterparties while broader biomass settlement is outside this change.

## Persistent account redemption

## Universal native search, November 9, 2026

The main native search window and map search now accept mixed categories through `search.Query` and `QuickQuery`. Results include active catalog agents/NPC characters, saved local pilots, NPC/player corporations, factions, constellations, systems, regions, stations and published item types. Deleted NPCs and unpublished item types are excluded. Known alliance, wormhole and structure categories return empty results because Eden has no searchable entities for those categories. Unknown categories, duplicate categories, invalid matching options and malformed requests reject without mutation.

Gameplay owns named search requests, categories, results and matching rules.
